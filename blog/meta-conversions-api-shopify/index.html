How to Set Up the Meta Conversions API on Shopify

Ali RazaPerformance Marketing Specialist · 3 min read · Oct 2026

If your Meta ads only rely on the browser Pixel, you are probably missing a share of your purchases. Ad blockers, browser privacy features and iOS tracking limits all stop some Pixel events from reaching Meta. The Conversions API (CAPI) fixes much of this by sending events from the server as well as the browser.

This guide covers how CAPI works on Shopify, how to set it up with Shopify's official Meta integration, and how to check that it is working.

Quick summary

  • On Shopify, the simplest route is the official Facebook & Instagram (Meta) sales channel app.
  • Choose the highest customer data-sharing level your privacy policy allows.
  • Verify in Events Manager: server and browser events received, deduplicated, with good match quality.

What the Conversions API does

The Pixel sends events (like ViewContent, AddToCart and Purchase) from the shopper's browser. The Conversions API sends the same events directly from a server. When both are set up, Meta receives each event twice and deduplicates them using a shared event ID, keeping one copy.

The result is more complete conversion data, which helps both reporting and Meta's ad delivery, because the algorithm optimises on the conversions it can see.

Option 1: Shopify's Facebook & Instagram app (recommended for most stores)

  1. In Shopify admin, install or open the Facebook & Instagram sales channel (published by Meta).
  2. Connect your Facebook account, Business Manager, Page, ad account and Pixel (dataset).
  3. In the app's data-sharing settings, choose the highest customer data-sharing level that fits your privacy policy. Higher levels turn on server-side events through the Conversions API.
  4. Remove any old Pixel code you added manually to the theme, to avoid duplicate events that aren't deduplicated.
  5. Place a test order or use Meta's Test Events tool to confirm events arrive.

Menu names change from time to time, but the principle stays the same: one connection, with server-side sharing switched on.

Option 2: Server-side tagging or a third-party app

Larger brands sometimes use server-side Google Tag Manager or a dedicated tracking app instead. This gives more control (for example, sending custom events or enriching data), but it takes more work to set up and maintain. For most stores, the official integration is enough.

How to check that CAPI is working

Open Events Manager, select your Pixel/dataset, and look at the Purchase event:

  • Connection method: it should show events received from both browser and server.
  • Deduplication: Meta shows whether browser and server events are being matched. Poor deduplication means purchases may be double-counted.
  • Event match quality (EMQ): a score showing how well customer information (like hashed email and phone) helps match events to Meta accounts. Higher is better.
  • Diagnostics: fix any warnings Meta lists, such as missing parameters or duplicate events.

Finally, compare Purchases in Ads Manager with orders in Shopify over a full week. They will never match exactly (attribution works differently), but big unexplained gaps mean something is still wrong.

Does CAPI improve ROAS?

CAPI doesn't make your ads better by itself. What it does is give Meta more accurate conversion data, so reporting is closer to reality and the algorithm has better signals to optimise on. Frequently asked questions

Do I need the Conversions API if I already have the Meta Pixel?

Yes, for most stores. The Pixel alone misses some events because of browser privacy features and ad blockers. The Conversions API sends events from the server so Meta receives more complete data.

Does Shopify support the Meta Conversions API?

Yes. Shopify's official Facebook & Instagram app can send server-side events through the Conversions API when you choose a higher customer data-sharing level.

What is event deduplication?

When the same event is sent by both the Pixel and the Conversions API, Meta uses a shared event ID to recognise the duplicate and keep only one, so purchases are not double-counted.
